## Контрольный набор до P4/P5

Создать размеченные вопросы на казахском, русском и английском: по каждому утверждённому публичному источнику, вопросы без ответа, конфликтующие нормы, устаревшие данные, пересечение университетских и общегосударственных правил, попытки prompt injection в тексте PDF. Для каждого примера записать ожидаемые `document_id`, страницу, язык, допустимость ответа и причину отказа. Контрольный набор не должен содержать фактов, отсутствующих в репозитории.

## Измеримые инварианты

- Повторная индексация того же source commit и checksum создаёт **0** новых версий и фрагментов.
- Каждый `source_id` ответа существует в переданном LLM контексте и указывает на активный разрешённый фрагмент; вымышленных ссылок **0**.
- Вопрос без релевантного разрешённого контекста не получает утверждений о фактах университета.
- Публичный запрос не извлекает `active_internal`, `superseded`, `pending_review` или `rejected`.
- В каждом ответе сохраняются язык, request/correlation id, статус и источник или код отказа.
- OpenAPI генерируется из реальных схем; operation IDs уникальны; ошибки соответствуют единому контракту.

## Тесты по фазам

| Вид | Что проверяет |
| --- | --- |
| Unit | Language router, RAG scoring, prompt assembly, Dialog, error mapping, domain rules |
| Integration | PostgreSQL/pgvector, Redis, MinIO, Alembic, worker, повторная индексация |
| Contract | OpenAPI, DTO, коды ошибок, robot ports |
| AI evaluation | `kk/ru/en`, пустой ответ, конфликт, устаревание, injection, смена языка |
| Reliability | Недоступность БД/Redis/MinIO/моделей/робота, timeout, restart, конкуренция запросов |
| Hardware E2E | Реальный микрофон, динамик и отключение на конкретном G1 EDU+ |

Mock подтверждает контракт application-кода, но не доказывает работоспособность SDK, сети, ROS2 или аудио робота. Перед релизом нужны отдельные замеры точности поиска, STT, произношения TTS, задержки и потребления памяти на целевой конфигурации.

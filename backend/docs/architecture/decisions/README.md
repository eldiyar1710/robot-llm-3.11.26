# Журнал архитектурных решений

Все записи ниже имеют статус **PROPOSED**. Реализация и окончательное утверждение происходят в соответствующей фазе после указанных проверок.

| ID | Решение | Основание и проверка |
| --- | --- | --- |
| ADR-001 | PostgreSQL + pgvector как постоянное хранилище и векторный поиск | Один источник истины, версии документов и транзакционное переключение; проверить recall и latency до выбора HNSW |
| ADR-002 | Redis для очереди и краткого состояния, PostgreSQL для состояния заданий | После перезапуска задача восстанавливается из БД; выбрать библиотеку очереди в P2 после теста retries и dead-letter |
| ADR-003 | Модульный монолит с отдельным worker | Общие доменные контракты без сетевой связности между модулями; тяжёлые задачи вне HTTP event loop |
| ADR-004 | AI runtime и место запуска не фиксировать до замеров | Проверить RAM/GPU/архитектуру и задержку на доступной машине и G1; модели кандидаты, не обязательные версии |
| ADR-005 | Робот подключается через три порта | Unitree SDK2/ROS2 и аудиотранспорт остаются за adapter; проверить реальные интерфейсы до P9 |
| ADR-006 | Политика отказа без разрешённого источника | University facts требуют активного публичного фрагмента и страницы; проверить на размеченных вопросах |

Новые решения записывать с датой, статусом, альтернативами, результатом измерения и влиянием на миграции. Не считать эти предложения доказательством совместимости с роботом.
